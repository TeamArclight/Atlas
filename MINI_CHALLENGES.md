# Mini-challenge options

Checked October 22, 2026 against https://amazonappdev2026.devpost.com/rules

## Open Source — recommended

Create a new additional open-source project or contribute to an existing public repository during the hackathon window. A branch, fork, or unmerged PR can qualify. Include contribution URL, Atlas repository URL, GitHub username, description, operation, and value. Importing dependencies or making Atlas public alone is not the additional contribution requirement.

Good Atlas contribution: extract the provider-independent plan graph validator with budget/approval/tool constraints, typed schemas, examples, and tests into a reusable package. This is proposed work, not yet extracted, published, or submitted. Preserve upstream attribution.

## AWS Builder — optional with Gemini

Bedrock specifically is not required. Rules allow documented qualifying AWS services/tools, including Strands SDK or Kiro Crew. Kiro Crew genuinely used in development qualifies on its own without an AWS runtime call. A real AWS integration can coexist with Gemini. Dependencies and unused Bedrock code are not evidence of integration.

Prioritize the working Alexa+ demo and useful Open Source contribution. Do not add superficial AWS features just to claim eligibility. Record actual tool usage and reproducible evidence. No new AWS deployment is authorized by this document.

There are two mini-challenge categories. A project can win at most one track prize and one mini-challenge prize. Eligibility is not a guarantee of judging outcome.
